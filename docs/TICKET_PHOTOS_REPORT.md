# گزارش وظیفه: فرم بهتر ارسال تیکت و پیوست عکس
وضعیت: انجام‌شده؛ 2026-10-14، به درخواست مالک.

### ۱) چه کاری انجام شد
فرم ارسال با کارت‌های برند، راهنما و بخش‌های موضوع/پیام/پیوست، شمارنده متن و پیش‌نمایش عکس بازطراحی شد. انتخاب یا drag/drop، حذف قبل از ارسال، حداکثر 3 عکس 5 MiB؛ ارسال اولیه و پاسخ بعدی با عکس، از جمله بدون JavaScript، کار می‌کند. عکس در گفت‌وگوی مشتری/اپراتور با لینک نمایش کامل و فقط دسترسی مجاز دیده می‌شود.

### ۲) فایل‌های تغییر‌یافته
TicketPhotoService/قراردادهای تیکت/MediaUploadService/IMediaStore؛ LocalMediaStore، TicketStore، TicketModel، entity و Migration/Snapshot/DI؛ کنترلر و مدل/خواندن محدودِ فایل؛ ویوهای ارسال/پاسخ/گفت‌وگو و photo picker؛ CSS و ticket-compose.js؛ تست‌های SQL/پاک‌سازی/فایل خصوصی؛ logging abstraction با نسخه 10.0.12 در manifests؛ SQL رفت/بازگشت و مستندات.

### ۳) تست‌های اجراشده و خروجی واقعی
- tool restore و restore؛ build -warnaserror: صفر هشدار/خطا.
- dotnet test --no-build با SQL Server 2022 Developer: 557 کل و موفق، صفر شکست/Skip؛ 419 واحد، 138 یکپارچه.
- آپلود واقعی، owner/staff read، IDOR/مهمان/مسیر عمومی، cache no-store، رد جعلی/حجم/تعداد، بازرمزگذاری، عکس پاسخ، cleanup در conflict و FK failure، commit نامشخص، cancellation/نام تصادم/هم‌پوشانی root آزموده شدند.
- Migration روی Dev/Test اعمال شد. DB جدا در schema قبلی یک تیکت/پیام آزمایشی داشت؛ up/down/reapply عکس موفق و پیام قبلی همچنان دقیقاً یک ردیف باقی ماند. در آماده‌سازی sqlcmd، QUOTED_IDENTIFIER برای ایندکس فیلترشده تنظیم شد؛ هیچ ایندکسی حذف/غیرفعال نشد.
- Chromium دسکتاپ 1440×1100 و موبایل 390×844: انتخاب 3 عکس، preview و حذف/drag-drop، حد تعداد، ارسال و مشاهده 3 عکس، عکس در پاسخ بعدی، private no-store و ارسال بدون JS موفق؛ overflow افقی صفحه نبود. تصاویر نمونه محلی و با برچسب LOCAL TEST PHOTO بودند.
- Node syntax، git diff --check و اسکریپت دسترس‌پذیری موجود موفق؛ این ممیزی کامل WCAG نیست.

### ۴) مشکلات باقی‌مانده
روی دیتابیس اصلی مالک Migration باید اجرا شود؛ هیچ دسترسی به آن استفاده نشده. اتصال sms.ir غیرفعال باقی است. مرورگرهای دیگر/Windows آزموده نشده‌اند. پاک‌سازی فایل بی‌ارجاع در crash/commit نامشخص فعلاً با تطبیق دستی انجام می‌شود.

### ۵) ریسک امنیتی
فایل‌ها بازرمزگذاری، نام تصادفی و پوشه خصوصی دارند؛ no-store و Policy/مالکیت در query اجباری‌اند. ساختار واقعی و اندازه سرور بررسی می‌شود؛ JS صرفاً UX است. فایل‌های ازپیش‌موجود در خطا حذف نمی‌شوند و مسیر عمومی/خصوصی هم‌پوشان پذیرفته نیست. متن/کلید/مسیر فیزیکی در لاگ/HTML عکس قرار نگرفت. پیوست‌های fixture واقعی مشتری خارجی نبودند.

### ۶) Migration لازم است؟
بله: 20261013214044_TicketPhotos. TicketPhotos.sql و TicketPhotosDown.sql موجود و آزموده هستند. Down metadata عکس‌ها را حذف می‌کند، پیام‌ها می‌مانند و فایل‌ها حذف نمی‌شوند؛ برای داده ارزشمند بدون backup/برنامه بازگشت اجرا نشود.

### ۷) به‌روزرسانی مستندات
PROJECT_STATUS، ROADMAP، CHANGELOG، DATA_MODEL، SECURITY، TESTING، DEPLOYMENT، KNOWN_LIMITATIONS، ADR-0017 و همین گزارش.

### ۸) قدم بعدی دقیق
مالک فرم جدید را بازبینی کند و هنگام اجرای این نسخه روی دیتابیس خود، Migration TicketPhotos را اعمال کند.
