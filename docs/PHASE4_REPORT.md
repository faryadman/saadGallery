## ۱. چه ساخته شد

ویترین محصولاتِ گالری: تعریف و مدیریت کالا توسط اپراتور/مدیر، بارگذاریِ امنِ تصویر،
تولیدِ بندانگشتی، انتشار/غیرفعال‌سازی، و نمایشِ عمومی با سیاستِ قیمتِ شفاف.

### رویهٔ عمومی (بدون نیاز به ورود)

| نشانی | توضیح |
|---|---|
| `/` | آخرین محصولات (۸ قلم، از `ProductOptions:HomeLatestCount`) |
| `/products` | ویترین کامل (۲۴ قلم، `CatalogPageSize`) |
| `/products/{id}` | جزئیات؛ **۴۰۴** اگر منتشرنشده یا حذف‌شده باشد |

### پنل اپراتور (فقط `Operator`/`Admin`، کنترل‌شده در سمت سرور)

| نشانی | عمل |
|---|---|
| `GET /Operator/Products` | فهرست مدیریتی (با گزینهٔ نمایشِ حذف‌شده‌ها) |
| `GET/POST /Operator/Products/Create` | ایجاد |
| `GET/POST /Operator/Products/Edit/{id}` | ویرایش |
| `POST /Operator/Products/Publish/{id}` | انتشار / لغو انتشار |
| `POST /Operator/Products/Delete/{id}` | حذفِ نرم |
| `POST /Operator/Products/RefreshPrice/{id}` | بازمحاسبهٔ قیمتِ `Computed` |
| `GET /Operator/Products/Images/{id}` | مدیریت تصویر |
| `POST /Operator/Products/Images/{id}/Upload` | بارگذاری (حداکثر ۱۰ مگابایت در درخواست) |
| `POST /Operator/Products/Images/Delete/{imageId}` | حذف تصویر (ردیف + هر دو فایل) |

همهٔ عملیاتِ تغییردهنده دارای `[ValidateAntiForgeryToken]` هستند و کلِ کنترلر با
سیاستِ `OperatorArea` (نقشِ `Operator` یا `Admin` **و** حسابِ فعال) محافظت می‌شود.

## ۲. معیارهای پذیرش — وضعیتِ تک‌تک

| معیار | وضعیت | شاهدِ اجراشده |
|---|---|---|
| مدیریت فقط با `Operator`/`Admin`، سمت سرور؛ درخواست مستقیمِ `Customer` ⇒ ۴۰۳ | ✅ | `ProductAuthorizationTests` — ۱۲ مورد: مهمان ⇒ ۳۰۲، `Customer` ⇒ **۴۰۳**، `Operator`/`Admin` از سد می‌گذرد |
| رد فایل غیرتصویری با پسوند/نوعِ جعل‌شده (بررسیِ **واقعیِ ساختار**) | ✅ | `SkiaImageProcessorTests` — ۱۷ مورد با نمونه‌های مسموم |
| محدودیتِ اندازه و تعداد | ✅ | ۵ مگابایت فایل · ۸ تصویر برای هر کالا · ۸۰۰۰ پیکسل (سدِ بمبِ پیکسلی) |
| نام فایل تصادفی، بدون نام کاربر | ✅ | `MediaFileNamingTests` — ۳۲ نویسهٔ هگز، یکتایی در ۵۰۰۰ فراخوان |
| ذخیره بیرون از پوشه کد | ✅ | `ProductMediaSecurityTests` — ریشه‌ها بیرون از `wwwroot` (و برنامه در صورت تخطی بالا نمی‌آید) |
| جداسازی تصاویر عمومی از فایل‌های خصوصی | ✅ | فایلِ خصوصی از `/media/products` ⇒ **۴۰۴**؛ تصویر عمومی ⇒ **۲۰۰** |
| بندانگشتی و بهینه‌سازی حجم | ✅ | ۴۸۰ پیکسل، WebP با کیفیت ۸۲، همیشه کوچک‌تر از نسخهٔ کامل |
| حذف/جایگزینی فقط با مجوز + Audit | ✅ | `UploadedByUserId` · `UploadedAtUtc` · نام/نوعِ ادعایی ثبت می‌شود |
| محصول منتشرنشده در هیچ لیست عمومی (ID ⇒ ۴۰۴) | ✅ | `ProductCatalogSqlTests` — شرط در خودِ پرس‌وجو |
| سیاست قیمت `Fixed`/`Computed`/`QuoteOnly`؛ ذخیره و نمایشِ مبنا و زمان | ✅ | ستون‌های `Price*`؛ `ProductPriceMathTests` فرمول را قفل کرده |
| موجودی/قیمت منسوخ **بدون هشدار** نمایش داده نشود | ✅ | `ProductPricePresentationTests` — ۱۵ مورد؛ در نبود/کهنگیِ مبنا **هیچ عددی** چاپ نمی‌شود |

### نکتهٔ امنیتیِ طراحی: ۴۰۴ نه ۴۰۳

وقتی `Customer` نشانیِ یک کالای منتشرنشده را صدا می‌زند، پاسخ **۴۰۴** است نه ۴۰۳.
۴۰۳ به معنای «این شناسه وجود دارد ولی اجازه نداری» است و وجودِ کالا را فاش می‌کند.
۴۰۳ فقط جایی استفاده می‌شود که معیارِ پذیرش صریحاً خواسته: **درخواستِ `Customer`
به صفحهٔ مدیریت** (که در آن وجودِ نشانی از پیش روشن است).

## ۵. محدودیتِ مهم دربارهٔ آزمون (صادقانه)

**SQL Server در محیطِ این عامل در دسترس نبود.** بنابراین:

- ۷ تستِ `ProductCatalogSqlTests` در اینجا **اجرا نشدند**؛ آن‌ها صریحاً Skip می‌شوند
  (Skip، نه سبزِ کاذب) تا زمانی که متغیر `SADGALLERY_TEST_SQL` تنظیم شود.
- برای اینکه منطقشان بی‌آزمون نماند، یک **میانجیِ موقت** (بیرون از مخزن، بعداً پاک شد)
  همان مسیرِ سرویس و دیسک را روی SQLite اجرا کرد: **۳۷ بررسی، همه PASS**. این شامل
  ردِ فایلِ اجرایی، ساختِ بندانگشتی، محدودیتِ تعداد، حذفِ فایل‌ها، جداسازیِ عمومی/خصوصی
  و ردِّ نام‌های عبور از مسیر بود.
- پرس‌وجوهای فهرست (که SQLite در `ORDER BY` روی `DateTimeOffset` پشتیبانی نمی‌کند)
  در آن میانجی اجرا نشدند و **فقط** روی SQL Server واقعی سنجیده می‌شوند.

**اقدامِ لازم روی دستگاه شما:**

```bash
export SADGALLERY_TEST_SQL="Server=.;Database=SadGallery_Test;Trusted_Connection=True;TrustServerCertificate=True"
./scripts/test.sh
```

## ۶. دو اشکال که در بازبینی پیدا و اصلاح شد

بازبینیِ پس از بازسازی دو ناهماهنگیِ واقعی نشان داد که در نوبتِ پیش دیده نشده بودند:

1. **ویترینِ عمومی ۸ قلم نشان می‌داد، نه ۲۴.**
  `/products` مقدار `take: null` می‌فرستاد، که در سرویس به `HomeLatestCount` (۸) می‌افتاد،
   نه `CatalogPageSize` (۲۴). اصلاح شد: اکنون اندازهٔ صفحهٔ ویترین صریحاً از تنظیمات می‌آید.

2. **ویترین با قطعِ دیتابیس استثنای خام به مرورگر می‌داد**، در حالی که صفحهٔ خانه
   از پیش این وضعیت را خوش‌برخورد مدیریت می‌کرد. اصلاح شد: `/products` اکنون پیامِ
   «ویترین در این لحظه در دسترس نیست» نشان می‌دهد و `/products/{id}` یک صفحهٔ اختصاصی
   دارد (نه ۴۰۴ِ دروغین — چون کالا ممکن است موجود باشد و فقط خواندنش ممکن نبوده).

یک پارامترِ زائد هم حذف شد: `AddImageAsync` نامِ کاربر را می‌گرفت اما هرگز استفاده
نمی‌کرد؛ نامِ نمایشی درست از جدول کاربران (مرجعِ هویت) خوانده می‌شود، نه از رشتهٔ ارسالیِ کلاینت.

## ۷. ارزیابیِ ریسک امنیتی

| ریسک | وضعیت | توضیح |
|---|---|---|
| اجرایِ کدِ راه‌دور از راهِ بارگذاری | 🟢 بسیار کم | تصمیم با رمزگشاییِ واقعی است؛ خروجی دوباره رمزگذاری می‌شود (ADR-0014) |
| Polyglot (تصویر + بارِ پنهان) | 🟢 کم | خروجی از پیکسل‌ها ساخته می‌شود، نه از بایت‌های ورودی |
| عبور از مسیر (Path Traversal) | 🟢 بسیار کم | دو سد: الگوی هگز + بازبینیِ مسیرِ نهایی |
| افشای فایل‌های خصوصی | 🟢 بسیار کم | پوشهٔ خصوصی هیچ مسیر ایستایی ندارد؛ تست شده |
| بمبِ پیکسلی / حافظه | 🟡 کم | محدودیتِ ابعاد از سرآیند، **پیش** از رمزگشایی اعمال می‌شود |
| بارِ CPU در بارگذاریِ همزمان | 🟡 متوسط | بدون محدودیتِ نرخِ اختصاصی برای بارگذاری؛ پیشنهاد در فاز ۸ |
| XSS از راهِ SVG | 🟢 ندارد | SVG اصلاً پذیرفته نمی‌شود |

**ریسکِ باقی‌مانده برای یادآوری به مالک:** «پنهان‌کردنِ دکمه هرگز کنترل امنیتی نیست»
در این فاز رعایت شده — کنترل در سمت سرور و با سیاستِ نقش است و تستِ ۴۰۳ این را اثبات می‌کند.

## ۸. مهاجرت — نیازمند اقدام

**بله.** جدول‌های `Products`، `ProductCategories`، `ProductImages` تازه‌اند و بدون
اجرای مهاجرت، صفحات ویترین با خطا روبه‌رو می‌شوند.

```bash
# ویندوز — در پنجره‌ای که رشته اتصال فقط در همان پنجره تنظیم شده (نه در فایل مخزن)
$env:ConnectionStrings__SadGallery = "Server=.;Database=SadGallery;Trusted_Connection=True;TrustServerCertificate=True"
dotnet ef database update --project src/SadGallery.Infrastructure --startup-project src/SadGallery.Web
```

مسیرِ جایگزین (اسکریپتِ دستی و idempotent): `database/scripts/AddProductsAndMedia.sql`

**سازگاری:** این مهاجرت **فقط جدول می‌افزاید** و هیچ جدول یا ستونِ موجودی را تغییر
نمی‌دهد؛ بنابراین با داده‌های فاز ۱–۳ سازگار است و بازگشتِ آن با حذفِ سه جدول ساده است.
**پیش از اجرا روی Production، پشتیبان کامل بگیرید** (`docs/DEPLOYMENT.md` §۶).

**تغییرِ پیکربندیِ همراه:** `StorageOptions:AllowedImageFormats` حذف شد — فهرستِ
قالب‌ها در کد ثابت است و تصمیم با رمزگشاییِ واقعی گرفته می‌شود، نه با فهرستِ پیکربندی.
اگر این کلید در تنظیمات سرور شما هست، بی‌اثر است (خطا نمی‌دهد) و می‌توانید آن را پاک کنید.
