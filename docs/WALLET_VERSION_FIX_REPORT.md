# گزارش وظیفه: رفع خطای Version و فعال‌سازی کیف مشتری
وضعیت: انجام‌شده · 2026-10-19

### ۱) چه کاری انجام شد
فرم اولین فعال‌سازی کیف، Version خالی را معتبر می‌داند چون کیف هنوز رکورد/RowVersion ندارد. مدل مستقل و nullable فقط برای این فرم است؛ نسخه غیرخالی خراب با پیام فارسی رد می‌شود. برای کیف موجود، کنترل نسخه تازه در Store زیر همان قفل SQL حفظ شد. فرم تنظیمات/بررسی همچنان نسخه اجباری با پیام فارسی دارند. راهنمای فعال‌سازی پیش از شارژ اضافه شد.

### ۲) فایل‌های تغییر‌یافته (مسیر + نوع تغییر)
`src/SadGallery.Web/Models/GoldForms.cs`: جداسازی GoldEnableForm، نسخه اختیاری ایجاد و پیام صریح فارسی فرم‌های اجباری. `Controllers/GoldController.cs`: رد نسخه خراب پیش از درخواست ذخیره. `Views/Gold/Wallet.cshtml`: راهنمای فعال‌کردن مشتری قبل از شارژ. `tests/SadGallery.Tests.Integration/Trading/GoldTradingSqlTests.cs`: رگرسیون مسیر واقعی HTTP از کیف فاقد رکورد تا شارژ، و کنترل نسخه کیف موجود. مستندات بخش۷ به‌روز شدند.

### ۳) تست‌های اجراشده و خروجی واقعی
- پیش از اصلاح: رگرسیون جدید با `dotnet test --no-build` خطا را بازتولید کرد؛ **633 موفق، 1 شکست، صفر Skip**. اولین POST فعال‌سازی با Version خالی به‌جای302،400 داد.
- پس از اصلاح: `dotnet build --no-restore -warnaserror -m:1 --disable-build-servers` صفر هشدار/خطا؛ `dotnet test --no-build` با SQL واقعی و تزریق امن رشته اتصال: **634 موفق، صفر شکست/Skip، 29.385 ثانیه**.
- رگرسیون با Identity و کوکی واقعی در DB یکتا: ایجاد با نسخه خالی/حذف‌شده، مانده اولیه صفر، فعال‌شدن دکمه شارژ، شارژ تومان و طلا با ارقام فارسی، رد نسخه خراب، حفظ کنترل نسخه مفقود/قدیمی کیف موجود، تغییر با نسخه صحیح و فارسی‌بودن پیام نسخه اجباری تنظیمات. داده آزمایشی در finally حذف شد.
- Chromium/Playwright، عرض390، DB جدا و مشتری واقعاً فاقد کیف: کلیک فعال‌سازی با فیلد Version خالی موفق شد؛ دکمه شارژ فعال و هر دو نوع تومان/طلا ذخیره شدند. نسخه خراب400 فارسی، تغییر وضعیت با نسخه تازه، غیرفعال/فعال‌کردن مجدد موفق؛ صفر خطای JS/سرریز صفحه. منبع شبکه Disabled و همه حساب‌ها/مقادیر مصنوعی بودند.
- تست‌های SW دوباره اجرا نشدند؛ این اصلاح فایل/منطق worker یا allowlist کش را تغییر نمی‌دهد.

### ۴) مشکلات باقی‌مانده / مسدودکننده‌ها
برای این باگ مورد باز باقی نماند. برنامه محلی مالک باید پس از دریافت تغییرات دوباره build و اجرا شود؛ صفحه قدیمی کیف را بازخوانی کند. محدودیت‌های نرخ آنلاین معتبر و فعال‌سازی واقعیِ قابلیت طبق گزارش اصلی باقی‌اند.

### ۵) ریسک امنیتی
کنترل Required به‌صورت سراسری خاموش نشد. فقط نسخه‌ای که برای ایجاد هنوز وجود ندارد اختیاری است؛ Store ایجاد یا تغییر را با رکورد واقعی داخل قفل تشخیص می‌دهد. نسخه مفقود/خراب/قدیمی کیف موجود همچنان رد می‌شود. نقش، CSRF، idempotency، تراکنش و دفتر مالی بدون تغییر ماندند؛ هیچ داده واقعی تغییر نکرد.

### ۶) Migration لازم است؟
خیر؛ schema و مدل EF تغییر نکرده‌اند. انتشار کد و restart کافی است. بازگردانی این اصلاح، خطای اولیه را برمی‌گرداند و به داده مالی دست نمی‌زند. Migration اولیه GoldTradingWallets همچنان برای نصب اولیه قابلیت لازم است.

### ۷) به‌روزرسانی مستندات
ROADMAP: معیارهای باگ با اجرای واقعی؛ BUGS: BUG-016 و علت نبود پوشش مسیر ایجاد اولیه؛ CHANGELOG و PROJECT_STATUS: وضعیت634 تست؛ گزارش اصلی کیف به این گزارش ارجاع دارد. تصمیم معماری جدید لازم نیست؛ رفتار با ADR-0022 منطبق است.

### ۸) قدم بعدی دقیق
پس از دریافت نسخه جدید و اجرای مجدد برنامه، در کیف مشتری روی «فعال‌کردن مشتری ویژه» بزنید؛ سپس نوع شارژ، مقدار و توضیح را وارد و ثبت کنید.
