## چه اضافه شد

### ویترین مشتری

- فیلتر بر اساس **گروه محصول** و **موجودی**؛ گروه‌های خالی از صفحهٔ عمومی پنهان‌اند.
- ورودی «بودجهٔ من (تومان)» در `/products`؛ ارقام فارسی/عربی و جداکنندهٔ هزارگان پذیرفته می‌شود.
- وقتی بودجه وارد شود، فقط کالاهای **منتشرشده، حذف‌نشده، موجود** با قیمت ثابت یا قیمت محاسبه‌شدهٔ معتبر و تازه، که مبلغشان از سقف بودجه بیشتر نیست، نمایش داده می‌شوند.
- پیشنهادها از گران‌ترین قیمتِ زیر سقف به ارزان‌تر مرتب می‌شوند تا گزینهٔ نزدیک‌تر به بودجه ابتدا دیده شود.
- قیمت استعلامی، بدون قیمت، یا Snapshot محاسبه‌شدهٔ کهنه در جست‌وجوی بودجه وارد نمی‌شود؛ رابط این محدودیت را صریحاً به مشتری می‌گوید. محصول منتشرنشده در SQL عمومی بیرون می‌ماند.
- جست‌وجو با GET انجام می‌شود، صفحه‌بندی دارد و هر فیلتر در نشانی قابل‌اشتراک است.
- ناوبریِ تکراریِ «محصولات (به‌زودی)» حذف شد؛ مسیر واقعیِ ویترین باقی است.

### مدیریت گروه‌ها

- اپراتور/مدیر می‌تواند گروه را **بسازد، نام/توضیح/ترتیبش را ویرایش کند**.
- Policy سمت سرور `OperatorArea` روی تمام مسیرهاست؛ POSTها ضدجعل دارند. تست HTTP، مهمان را به ورود می‌فرستد و `Customer` را با **۴۰۳** رد می‌کند.
- حذف گروه ارائه نشده تا با یک کلیک، گروه‌بندیِ کالاهای موجود از بین نرود. تغییر نام/ترتیب، گروه‌های وابسته را نگه می‌دارد.

### گروه‌های نمونه و دادهٔ محصولِ نیازمند مالک

`database/scripts/SeedGoldCategories.sql` یک اسکریپت **idempotent** برای افزودن ۶ گروه آماده می‌کند: انگشتر، گردنبند و زنجیر، دستبند، گوشواره، پلاک و آویز، نیم‌ست و ست.

**هیچ ردیف محصولی ساخته نشده است.** ستون‌های درصد اجرت/سود/مالیات در schema فعلی اجباری‌اند (`NOT NULL`)؛ پرکردن آن‌ها با صفر فقط برای دور زدن schema، جعلِ دادهٔ مالی بود. از آنجا که مالک هنوز عنوان واقعی، موجودی و قیمت یا وزن/عیار/درصدهای تأییدشده نداده، درج پیش‌نویس محصول را متوقف کردم و Migration بی‌درخواست اضافه نکردم. برای ساخت چند محصول، اطلاعات واقعی لازم است؛ اگر draft با فیلدهای مالی خالی لازم باشد، ابتدا باید دربارهٔ nullable کردن این ستون‌ها و Migration سازگار تصمیم گرفته شود.

`ProductBudgetInputTests` ارقام فارسی/عربی، جداکننده‌ها، ورودی نامعتبر و حد را می‌سنجد.
تست دسترسی دسته‌ها در مسیر واقعی HTTP اجرا شد. دو تست تازهٔ `ProductCatalogSqlTests`
(فیلتر دسته/بودجه/تازگی قیمت و CRUD گروه) نوشته شده‌اند، اما همراه تست‌های SQL دیگر

ماشین مالک/CI اجرا شود؛ نتیجهٔ سبز ادعا نمی‌شود.

## داده، مهاجرت و اقدام لازم

- این افزوده **Migration تازه ندارد**؛ از جدول `ProductCategories` و ستون‌های قیمتِ فاز ۴ استفاده می‌کند.
- اگر مهاجرت پایهٔ `20261010084707_AddProductsAndMedia` هنوز اعمال نشده، ابتدا آن را اجرا کنید.
- سپس (اختیاری) فقط گروه‌ها را با اجرای اسکریپت زیر در SSMS یا `sqlcmd` اضافه کنید:

  ```text
  database/scripts/SeedGoldCategories.sql
  ```

- اسکریپت محصول یا قیمت نمی‌سازد. **در این سندباکس هیچ ردیفی به دیتابیس واقعی اضافه نشد**: اتصال SQL Server مالک در اختیار نبود.
- برای فعال شدن پیشنهاد بودجه، مالک باید اطلاعات واقعی کالا بدهد و اپراتور آن را با دستهٔ درست، موجودی تأییدشده و قیمت ثابتِ تومانیِ تأییدشده یا دادهٔ واقعی برای `Computed`، درصدهای تأییدشده و Snapshot تازه وارد و منتشر کند.

## اطلاعات لازم برای محصولات قابل‌نمایش

برای هر کالای واقعی یکی از این دو حالت را بفرستید/در پنل ثبت کنید:

1. **قیمت ثابت:** عنوان و گروه، مبلغ قطعی با واحد صریح (تومان)، موجودی و تصویرِ مجاز؛ یا
2. **قیمت محاسبه‌شده:** عنوان و گروه، وزن واقعی بر حسب گرم، عیار واقعی، درصدهای اجرت/سود/مالیاتِ مورد تأیید و سیاستِ نرخ مرجع.

این افزوده واحد موجودِ برنامه را «تومان» می‌گیرد؛ **هیچ تبدیل ریال به تومان انجام نمی‌شود**.
تا وقتی چنین اطلاعاتی نداریم، هیچ محصولی درج نمی‌شود و دادهٔ ساختگی منتشر نخواهد شد.

## امنیت و ریسک‌های باقیمانده

- کنترل دسترسی دسته‌ها سمت سرور است؛ پنهان‌کردنِ پیوند UI جای Policy را نمی‌گیرد.
- قیمت‌های بودجه در SQL از ردیف‌های منتشرشده و فقط با مقدار مثبت و معتبر انتخاب می‌شوند؛ ورودی سقف بودجه مثبت و محدود به `decimal(18,2)` است.
- ریسک باقیمانده: چون آزمون SQL واقعی اجرا نشده، باید query و CRUD دسته روی SQL Server هدف تأیید شود.
- هیچ قیمت/وزن/عیار/نرخی حدس زده نشده؛ ولی تا ثبتِ کالاهای واقعی و انتشارشان، پیشنهادهای بودجه ممکن است خالی بماند.

**گام بعد:** اجرای مهاجرت پایه (اگر لازم است)، اجرای `SeedGoldCategories.sql` روی SQL Server، دریافت مشخصات واقعی چند محصول (یا تصمیم جداگانه درباره nullable کردن درصدها)، اجرای تست‌ها با `SADGALLERY_TEST_SQL` و سپس تأیید مالک.
