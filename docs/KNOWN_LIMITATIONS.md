# محدودیت‌های صادقانه — SadGallery

> این سند «چیزهایی است که این محصول نمی‌تواند یا هنوز نمی‌تواند انجام دهد». شفاف بودن درباره محدودیت‌ها بخشی از کیفیت است، نه ضعف آن.

## ۱. محدودیت‌های محیط توسعه (سندباکس ایجنت)
| محدودیت | تأثیر | راه‌حل |
| --- | --- | --- |
| .NET SDK از پیش نصب نیست و نصب در `/opt/dotnet` ماندگار نیست | هر جلسه ~۷ ثانیه نصب مجدد (آزمون‌شده: SDK 10.0.401) | `scripts/dev-setup.sh` — **Build و Unit Test در سندباکس ممکن است** |
| SQL Server و Docker در دسترس نیست | تست‌های یکپارچه وابسته به DB اجرا نمی‌شوند | Trait `RequiresSqlServer` + اجرا روی ماشین مالک؛ در گزارش صریحاً «اجرا نشده» ثبت می‌شود |
| ۲ vCPU / ~2GB RAM | Build سنگین کند است؛ اجرای هم‌زمان سرویس‌ها محدود | فقط کارهای سبک؛ Job سنگین در سندباکس اجرا نمی‌شود |
| دسترسی شبکه محدود | اتصال به APIهای ایرانی نرخ از سندباکس ممکن است ممکن نباشد | کار با Fixture؛ اتصال واقعی روی سرور مالک آزمون می‌شود |
| پیش‌نمایش مرورگر در سندباکس بدون شبکه بیرونی | طبق درخواست، فقط **یک** سرویس وب **مستقل** (غیروابسته به .NET) در این محیط اجرا می‌شود | استقرار واقعی در محیط مالک |

## ۲. محدودیت‌های محصول (نسخه اول، آگاهانه)
| محدودیت | دلیل تصمیم | برنامه آینده |
| --- | --- | --- |
| بدون چت زنده، Push Notification و پیامک اعلان | طبق سند اصلی به مراحل بعد موکول شده؛ تیکت استاندارد و قابل اتکا مقدم است | پس از تثبیت تیکت (فاز ۵+)، با ارزیابی هزینه پیامک |
| بدون پرداخت آنلاین و درگاه بانکی | خارج از دامنه نسخه اول (محصول «ویترین + استعلام قیمت» است، نه فروشگاه تراکنشی) | تصمیم مالک؛ نیازمند الزامات مالی/حقوقی جداگانه |
| تاریخچه نرخ فقط از زمان شروع جمع‌آوری خودمان | API تاریخی منبع تأیید نشده (`Q-API-1` قلم A11) | اگر منبع آرشیو دارد، ایمپورت مستند |
| نمودارها بدون تحلیل تکنیکال و پیش‌بینی | جلوگیری از ارائه توصیه سرمایه‌گذاری غیرمسئولانه | در صورت درخواست مالک، با سلب‌مسئولیت صریح |
| نرخ‌ها «جهت اطلاع» است، نه نرخ معامله | تفاوت نرخ تابلو و نرخ واقعی معامله در بازار طلا؛ جلوگیری از سوءتفاهم | متن سلب‌مسئولیت در UI + شرایط استفاده |
| بدون چند‌زبانه (فقط فارسی) | دامنه محصول | افزودن `en` با Resource در صورت نیاز |
| بدون چند‌فروشگاهی/چند‌نمونه‌ای پیچیده | مقیاس یک فروشگاه | طراحی فعلی چند‌نمونه‌ای را پشتیبانی می‌کند (قفل Job) اما Load Balancing/Multi-tenant طراحی نشده |

## ۳. محدودیت‌های فنی PWA (واقعیت، نه شعار)
| موضوع | Android (Chrome) | iOS (Safari 16.4+) |
| --- | --- | --- |
| نصب | پیشنهاد خودکار نصب (beforeinstallprompt) | **بدون** پیشنهاد خودکار؛ کاربر باید Share → Add to Home Screen (نیاز به راهنمای دستی) |
| Service Worker | کامل | پشتیبانی‌شده (از iOS 11.3) با محدودیت |
| Push Notification | پشتیبانی کامل | فقط از iOS 16.4 و **فقط اگر اپ به Home Screen اضافه شده باشد**؛ در غیر این صورت خیر |
| Background Sync | پشتیبانی | **بدون پشتیبانی** |
| دوام Storage | پایدار | ممکن است توسط سیستم در فشار حافظه **پاک شود** (بدون اطمینان از ماندگاری کش) |
| دسترسی به سخت‌افزار (بلوتوث/NFC/فایل‌سیستم) | محدود | بسیار محدود یا ناموجود |
| نصب از خارج Store | ممکن | ممکن، اما با محدودیت‌های بالا |

**نتیجه عملی برای این پروژه:** نمایش نرخ از Cache در iOS ممکن است پس از مدتی از دست برود؛ صفحه آفلاین باید طوری طراحی شود که نبود داده را واضح بگوید، نه صفحه سفید. اگر در آینده Push واقعی و پایدار لازم شد (اعلان نرخ)، باید **اپلیکیشن بومی** یا سرویس واسط ارزیابی شود — تصمیم آن با مالک و پس از تثبیت نسخه وب.

## ۴. محدودیت‌های امنیتی که پذیرفته‌ایم (شفاف)
- امنیت صددرصدی وجود ندارد؛ این سند و `SECURITY.md` §9 فهرست ریسک‌های باقی‌مانده را نگه می‌دارند.
- OTP از طریق SMS: در برابر SIM-Swap و رهگیری اپراتوری، ایمن نیست (محدودیت صنعت).
- اگر سرور به‌طور کامل تصرف شود، Mantra «Passphrase در حافظه برنامه است» ⇒ مهاجم می‌تواند رازها را رمزگشایی کند؛ هدف طراحی، مقاومت در برابر «نشت دیتابیس/پشتیبان» است، نه «تصرف کامل سرور». (کاهش ریسک: دسترسی حداقلی، جداسازی Secret Store در فاز ۸).
- `NationalId` رمزنگاری‌شده است اما اگر کاربر خودش آن را در تیکت تایپ کند، در متن تیکت (بدون رمزنگاری) ثبت می‌شود ⇒ آموزش اپراتور + ماسک‌سازی خودکار الگوهای شبیه کد ملی در متن تیکت (فاز ۵).

## ۵. محدودیت‌های فرایندی
- تا زمانی که مالک پاسخ‌های `OPEN_QUESTIONS.md` را نداده، **هیچ ادعای صحت نرخ و هیچ اتصال واقعی به API** انجام نمی‌شود.
- تست‌های اجرانشده در سندباکس، در وضعیت فاز «انجام‌شده» شمرده نمی‌شوند؛ فازها فقط با اجرای واقعی روی محیط دارای SQL Server تأیید می‌شوند.
