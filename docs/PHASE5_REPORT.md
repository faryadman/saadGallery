# گزارش وظیفه: فاز ۵ — تیکت و استعلام قیمت
وضعیت: پیاده‌سازی و آزمون انجام‌شده؛ بازبینی مالک باقی است. پیامک به خواسته مالک غیرفعال است.

### ۱) چه کاری انجام شد
ثبت درخواست و استعلام مرتبط با کالای منتشرشده؛ گفت‌وگوی مشتری؛ صف/فیلتر اپراتور؛ یادداشت داخلی؛ ارجاع به اپراتور فعال؛ چرخه وضعیت و بازگشایی؛ شماره پیگیری یکتا؛ زمان پاسخ اول/آخرین فعالیت/بسته‌شدن؛ تاریخچه و ثبت رخداد امنیتی. مسیرها: `/tickets`، `/tickets/new`، `/tickets/{guid}` و `/operator/tickets`، `/operator/tickets/{guid}`.

### ۲) فایل‌های تغییر‌یافته
`Domain/Tickets` قواعد؛ `Application/Tickets` سرویس و قرارداد؛ `Infrastructure/Tickets` و `Persistence/TicketModel` ذخیره‌سازی/مدل؛ entityها و Migration/Snapshot؛ کنترلر/مدل/ویوهای مشتری و اپراتور؛ Program/DI/RateLimitPolicies؛ Layout و پیوند استعلام در جزئیات محصول؛ appsettings با جای خالی sms.ir. سه فایل تست جدید و اصلاح آماده‌سازی دو مجموعه تست قدیمی. اسکریپت SQL رفت/بازگشت در `database/scripts`.

### ۳) تست‌های اجراشده و خروجی واقعی
- .NET SDK 10.0.401 و dotnet-ef 10.0.12؛ restore و `dotnet build --no-restore -warnaserror -m:4`: صفر هشدار/خطا.
- `dotnet test --no-build` با SADGALLERY_TEST_SQL امن برای دیتابیس آزمایشی: 546 کل، 546 موفق، صفر شکست/Skip؛ 411 واحد و 135 یکپارچه. اجرای مجدد نیز سبز بود.
- پیش از اصلاح تست‌های قدیمی: دو شکست Seed ناشی از default متفاوت Identity، دو شکست نرخ ناشی از باقیماندن داده/lease؛ آماده‌سازی اصلاح شد، هیچ assertion حذف نشد.
- مهاجرت همه فازها روی دیتابیس خالی SQL Server 2022 Developer؛ بازگشت TicketsSchema به AddProductsAndMedia و اعمال مجدد روی دیتابیس جداگانه: موفق.
- HTTP واقعی Kestrel: `/health` و `/health/ready` و `/market/gold` = 200؛ مسیر مشتری و اپراتور برای مهمان = 302 به ورود. تست Identity دو مشتری و اپراتور واقعی، CSRF و IDOR 404 و نشت یادداشت/XSS هم سبز است.

### ۴) مشکلات باقی‌مانده / مسدودکننده‌ها
الگوی sms.ir و پارامترها مشخص نیست؛ adapter ارسال واقعی عمداً پیاده/فعال نشده. اطلاعات محصول واقعی و تأیید جداگانه ۴.۱ همچنان از مالک لازم است. تست Windows/IIS و دیتابیس هدف مالک اجرا نشده‌اند. ضمیمه اختیاری و SLA خارج از دامنه فعلی‌اند.

### ۵) ریسک امنیتی
محرمانگی مالکیت/یادداشت داخلی، CSRF، Encoding، RowVersion و limiter آزموده شدند. Rate limiter درون پردازش است؛ استقرار چندنمونه‌ای به limiter مشترک نیاز دارد. SQL محلی فقط روی loopback و در حالت Developer است؛ راز آن بیرون Git با دسترسی 600 نگهداری می‌شود. اطلاعات تست در دیتابیس جداست؛ داده مالی واقعی ساخته نشده. HTTPS عملیاتی/backup/کلیدهای DataProtection هنوز مربوط به فاز ۸ است.

### ۶) Migration لازم است؟
بله: `20261013201424_TicketsSchema`، چهار جدول SupportTickets/TicketMessages/TicketInternalNotes/TicketEvents. اسکریپت افزایشی ایدمپوتنت و `TicketsSchemaDown.sql` موجود و بازگشت روی دیتابیس آزمایشی آزموده شد. Down داده تیکت را حذف می‌کند؛ فقط در محیط غیرتولیدی بدون داده لازم، یا پس از backup و بازبینی. روی دیتابیس مالک اعمال نشده است.

### ۷) به‌روزرسانی مستندات
AGENTS، PROJECT_STATUS، ROADMAP، CHANGELOG، DATA_MODEL، SECURITY، TESTING، OPEN_QUESTIONS، BUGS، KNOWN_LIMITATIONS، ADR-0016 و همین گزارش.

### ۸) قدم بعدی دقیق
مالک رفتار تیکت و استعلام را بازبینی کند؛ sms.ir تا تعیین الگو و پیاده‌سازی ارسال واقعی غیرفعال می‌ماند. فاز ۶ بدون درخواست جداگانه آغاز نشده است.
