## 2. چه چیزی واقعاً انجام شده است (فاز صفر)

- بررسی مخزن: مخزن **خالی** بود (بدون Git، بدون `.sln`، بدون کد).
- بررسی محیط سندباکس (با اجرای واقعی): Debian 13، ۲ vCPU، ۱.۹GB RAM، Node 20، git 2.47.3، بدون Docker و بدون SQL Server و **بدون .NET SDK از پیش نصب‌شده**.
- **آزمون عملی ابزار:** نصب موفق `SDK 10.0.401` (Host 10.0.12) با `scripts/dev-setup.sh`؛ وجود قالب `mvc`؛ **دسترسی NuGet تأیید شد** (restore موفق `Microsoft.EntityFrameworkCore.SqlServer 10.0.12` در ۳.۵ ثانیه) ⇒ نتیجه: فاز ۱ در همین سندباکس قابل Build و Unit Test است.
- بررسی نسخه‌های روز: .NET 10 (LTS، آخرین Patch: 10.0.12 در 2026-09-08، پشتیبانی تا 2028-11-14)، Bootstrap 5.3.8، .NET 8/9 در حال پایان پشتیبانی (2026-11-10) ⇒ انتخاب .NET 10 درست و لازم است.
- بررسی اجمالی سرویس‌های نرخ ایرانی و شکل خروجی JSON آن‌ها (رایج: ساختار کلید/مقدار + زمان؛ مثال‌های مورد بررسی: `api.tala.ir`, `navasan.tech`, `nerkh-api.ir` — هیچ‌کدام تأییدشده مالک نیستند).
- ایجاد مخزن Git و ۲۰ سند دائمی + ۲ اسکریپت + ADR-0001 تا ADR-0009.
- تدوین معیارهای پذیرش آزمون‌پذیر برای فازهای ۰ تا ۸.

| نصب‌نشدن SQL Server در سندباکس ⇒ عدم اجرای تست‌های یکپارچه | متوسط (فرایند) | Build/Unit سبز؛ ۱۸ تست SQL با Skip صریح؛ تأیید query واقعی روی SQL Server مالک/CI لازم است |
| نبود دادهٔ واقعی محصول | متوسط (عملکرد/اعتماد) | هیچ محصول نمونه/قیمت جعلی درج نشده؛ پیشنهاد بودجه تا ورود اطلاعات تأییدشده می‌تواند خالی باشد |
| draft محصول با درصدهای نامشخص | متوسط (صحت داده) | سه ستون درصد فعلی NOT NULL؛ تا تصمیم مالک Migration nullable نمی‌سازیم و صفر را جایگزین نمی‌کنیم |

## 6. قدم بعدی دقیق

۱) **مالک/CI** روی SQL Server واقعی تست‌های Integration را با `SADGALLERY_TEST_SQL` اجرا کند، مخصوصاً ۱۸ تست SQL (شامل `BudgetSearch_OnlyReturnsPublishedInStockFreshPricedProductsInSelectedCategory` و `CategoryService_CreatesUpdatesAndRejectsDuplicateNames`). دستورها در `docs/TESTING.md` هستند؛ رشتهٔ اتصال/رمز را در Git، لاگ یا چت نفرستید.
۲) پس از تأیید migration فاز ۴ روی دیتابیس هدف، مالک در SSMS یا `sqlcmd` فقط گروه‌های اولیه را با `database/scripts/SeedGoldCategories.sql` درج کند؛ این اسکریپت محصول نمی‌سازد.
۳) مالک اطلاعات واقعی چند محصول را طبق `Q-CATALOG-1` ارائه کند یا محصول‌ها را از پنل وارد کند. اگر محصولات draft باید درصدهای مالی نامشخص داشته باشند، ابتدا پاسخ `Q-CATALOG-DRAFT-1` و تأیید Migration لازم است؛ تا آن زمان صفر ساختگی ثبت نمی‌شود.
۴) پس از گزارش نتیجهٔ SQL و بازبینی اطلاعات، مالک فاز ۴.۱ را تأیید یا اصلاحات لازم را مشخص کند. فاز بعدی تا این gate آغاز نمی‌شود.
۵) مسیرهای بازِ قبلی (`Q-API-1`, `Q-ENV-1`, `Q-SMS-1`) در فازهای مربوط خود پیگیری می‌شوند؛ این‌ها مجوز حدس‌زدن دادهٔ واقعی نیستند.
