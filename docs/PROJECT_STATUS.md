## 2. چه چیزی واقعاً انجام شده است (فاز صفر)

- بررسی مخزن: مخزن **خالی** بود (بدون Git، بدون `.sln`، بدون کد).
- بررسی محیط سندباکس (با اجرای واقعی): Debian 13، ۲ vCPU، ۱.۹GB RAM، Node 20، git 2.47.3، بدون Docker و بدون SQL Server و **بدون .NET SDK از پیش نصب‌شده**.
- **آزمون عملی ابزار:** نصب موفق `SDK 10.0.401` (Host 10.0.12) با `scripts/dev-setup.sh`؛ وجود قالب `mvc`؛ **دسترسی NuGet تأیید شد** (restore موفق `Microsoft.EntityFrameworkCore.SqlServer 10.0.12` در ۳.۵ ثانیه) ⇒ نتیجه: فاز ۱ در همین سندباکس قابل Build و Unit Test است.
- بررسی نسخه‌های روز: .NET 10 (LTS، آخرین Patch: 10.0.12 در 2026-09-08، پشتیبانی تا 2028-11-14)، Bootstrap 5.3.8، .NET 8/9 در حال پایان پشتیبانی (2026-11-10) ⇒ انتخاب .NET 10 درست و لازم است.
- بررسی اجمالی سرویس‌های نرخ ایرانی و شکل خروجی JSON آن‌ها (رایج: ساختار کلید/مقدار + زمان؛ مثال‌های مورد بررسی: `api.tala.ir`, `navasan.tech`, `nerkh-api.ir` — هیچ‌کدام تأییدشده مالک نیستند).
- ایجاد مخزن Git و ۲۰ سند دائمی + ۲ اسکریپت + ADR-0001 تا ADR-0009.
- تدوین معیارهای پذیرش آزمون‌پذیر برای فازهای ۰ تا ۸.

## 4. مسدودکننده‌ها و ورودی‌های لازم از مالک

| کد | موضوع | چرا مسدودکننده است | جایگزین تا زمان پاسخ |
| --- | --- | --- | --- |
| `Q-API-1` | نمونه JSON واقعی + مستندات API نرخ طلا/سکه/ارز/رمزارز | نگاشت DTO، واحدها (ریال/تومان)، زمان اعلام، محدودیت نرخ درخواست، استعلام دوره‌ای — بدون آن **تولید نرخ ممنوع است** | فقط لایه Provider و DTO نمونه (Fixture تست) پیاده می‌شود؛ اتصال واقعی نه |
| `Q-ENV-1` | محیط استقرار واقعی (Windows/IIS؟ Linux+VPS؟ Docker؟) و نسخه SQL Server | تعیین Kestrel/IIS، مسیر Secret، روش Backup/HTTPS، اندازه KDF | طراحی خنثی نسبت به میزبان + ADR باز |
| `Q-SMS-1` | ارائه‌دهنده پیامک OTP (کاوه‌نگار/sms.ir/…) و اعتبار/الگو | پیاده‌سازی واقعی OTP و تست انتها به انتها | رابط `ISmsSender` + پیاده‌سازی `LoggingSmsSender` فقط در Dev (با علامت هشدار) |
| `Q-DEVDB-1` | آیا مسیر Dev-only با SQLite برای پیش‌نمایش UI در سندباکس مجاز است؟ | اجرای برنامه (نه فقط تست واحد) در سندباکس به دیتابیس نیاز دارد | تا تصمیم: طبق `ADR-0002` فقط SQL Server. **وضعیت: غیرمسدودکننده** — Build و Unit Test بدون دیتابیس کار می‌کنند؛ فقط اجرای زنده UI در سندباکس ممکن نیست. مالک می‌تواند روی ماشین خود اجرا کند |

## 6. قدم بعدی دقیق

۱) مالک به پرسش‌های `docs/OPEN_QUESTIONS.md` (به‌ویژه `Q-API-1`) پاسخ می‌دهد و فاز صفر را تأیید می‌کند.

`SadGallery.sln` + `Domain/Application/Infrastructure/Web` + `Tests.Unit` + Identity با SQL Server + مهاجرت اولیه + صفحه سلامت `/health` + یک تست واحد و یک تست یکپارچه پایه، همه با `dotnet build -warnaserror` و `dotnet test` واقعی.
۳) در همان گام، `docs/PROJECT_STATUS.md` و `docs/CHANGELOG.md` به‌روزرسانی می‌شوند.
