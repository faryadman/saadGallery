# گزارش وظیفه: جدول تیکت، عملیات وضعیت و فیلتر یکدست
وضعیت: انجام‌شده؛ 2026-10-14، بر اساس بازخورد مالک درباره یکدستی با صفحات قبلی.

### ۱) چه کاری انجام شد
مرجع واقعی `Categories/Index` و `Products/Index` برای header، sg-table، badgeها و دکمه‌های عملیات، و `Views/Products/Index` برای کادر/کنترل فیلتر استفاده شد. جدول مشترک هفت ستون دارد: پیگیری، موضوع و زمان ثبت، نوع، وضعیت، فعالیت/پاسخ اول، اتمام، عملیات. اپراتور مشاهده/پاسخ، شروع بررسی، اتمام و بازگشایی دارد؛ مشتری مشاهده/پاسخ و فیلتر درخواست‌های خودش دارد. خالی بودن نتایج درون جدول توضیح داده می‌شود؛ داده تجاری ساختگی ساخته نشد.

### ۲) فایل‌های تغییر‌یافته
`TicketContracts` و projection خلاصه در `TicketStore` برای RowVersion؛ دو کنترلر تیکت برای فیلتر مشتری و POST وضعیت اپراتور؛ `TicketForms`/`TicketLabels`/`TicketListViewModel`؛ دو ویوی Index و partialهای مشترک `_TicketFilters`/`_TicketTable`؛ برچسب وضعیت در جزئیات اپراتور؛ دو فایل تست یکپارچه؛ AGENTS و مستندات وضعیت/طرح/تغییرات/ADR و این گزارش.

### ۳) تست‌های اجراشده و خروجی واقعی
- ابزار/دستورهای ثبت‌شده محیط فعال و `dotnet tool restore`، restore و `dotnet build --no-restore -warnaserror -m:4` اجرا شدند: صفر هشدار/خطا.
- `dotnet test --no-build` با SQL Server واقعی آزمایشی: 547 موفق، صفر شکست/Skip (411 واحد، 136 یکپارچه).
- POST وضعیت: مشتری رد شد؛ بستن New رد شد؛ شناسه ناموجود 404؛ نسخه قدیمی 409؛ اتمام مجاز، زمان بسته‌شدن و بازگشت search/status/from/until آزموده شد.
- Chromium 1440×1100 و 390×844: سه درخواست آزمایشی محلی، فهرست مشتری بدون کنترل مدیریتی، مرجع گروه‌بندی، جدول هفت‌ستونی، شروع→پاسخ→اتمام→بازگشایی، badge و زمان اتمام، فیلتر وضعیت/جست‌وجو/تاریخ و scroll محدود به جدول در موبایل بررسی شدند.
- `python3 scripts/accessibility-check.py`: همه 23 جفت‌رنگِ پالت موجود و معیارهای لمس اسکریپت قبول؛ ممیزی کامل WCAG نیست.
- `git diff --check`: موفق. تصویر بررسی در `/workspace/.sadgallery-tools/ticket-operator-table.png` و `ticket-completed-table.png` و `ticket-table-mobile.png` است؛ حساب/درخواست‌های داخل آن آزمایشی محلی‌اند.

### ۴) مشکلات باقی‌مانده
تأیید ظاهری مالک باقی است؛ پیامک طبق خواسته قبلی غیرفعال است. مرورگرهای دیگر آزموده نشدند.

### ۵) ریسک امنیتی
تمام عملیات وضعیت با Policy/CSRF/RowVersion/RateLimit و همان قواعد وضعیت انجام می‌شوند. اتمام تیکت New/InReview تا رسیدگی و پاسخ غیرفعال است و با درخواست مستقیم نیز رد می‌شود. مشتری نمی‌تواند وضعیت تیکت را تغییر دهد. یادداشت داخلی در جدول/فیلتر مشتری نیست. این کار دسترسی تولید یا سرویس خارجی ایجاد نکرد.

### ۶) Migration لازم است؟
خیر. فقط RowVersion موجود در DTO فهرست استفاده شد؛ schema تغییر نکرد.

### ۷) به‌روزرسانی مستندات
