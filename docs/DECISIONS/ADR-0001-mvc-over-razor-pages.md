# ADR-0001 — ASP.NET Core MVC به‌جای Razor Pages یا Blazor

- **وضعیت:** Accepted
- **تاریخ:** 2026-10-05
- **تصمیم‌گیر:** مالک پروژه (طرح پیشنهادی تیم فنی)

## زمینه
محصول شامل چند «سایت» با رفتار متفاوت است: بخش عمومی (صفحات نرخ/نمودار)، داشبورد مشتری، پنل اپراتور، پنل مدیر. UI فارسی RTL با Bootstrap 5 الزامی است.

## تصمیم
ASP.NET Core **MVC** با Areas (`Admin`, `Operator`, `Account`) در پروژه `SadGallery.Web`.

## دلیل
1. تفکیک روشن نقش‌ها در Areas با کنترلرهای متمرکز، برای پروژه‌ای با نقش‌ها و فرم‌های زیاد، از Razor Pages خواناتر است.
2. Blazor (Server/WASM) با الزامات PWA و Cache و راهبرد استقرار ساده‌تر این پروژه، پیچیدگی عملیاتی افزوده می‌کرد (WebSocket برای Blazor Server / حجم WASM). هیچ سود واقعی برای این دامنه نداشت.
3. افزودن APIهای JSON (برای نمودار و PWA) در MVC طبیعی است.
4. Bootstrap + TagHelperهای سمت سرور، سبک و قابل نگهداری برای مالک پروژه است.

## پیامدها
- **مثبت:** ساختار آشنا و پر‌مستند؛ تعداد کم فایل برای هر صفحه؛ سازگاری با سرور ضعیف.
- **منفی:** برای بخش‌های تعاملی بیشتر (مثل صف تیکت با به‌روزرسانی زنده) باید کمی JavaScript افزوده شود (در نسخه اول با Polling ساده یا Refresh صفحه مدیریت می‌شود).

## جایگزین‌های بررسی‌شده
- **Razor Pages:** برای فرم‌های تک‌صفحه‌ای خوب است، اما با ۴ ناحیه مجزا و روابط پیچیده بین صفحه‌ها، پراکندگی منطق ایجاد می‌کرد.
- **Blazor Server:** نیاز به اتصال پیوسته و مدل حالت سرور؛ برای بخش نرخ عمومی که باید در تعداد زیاد بازدید کار کند، مناسب نیست.
- **Blazor WASM:** حجم اولیه بالا برای کاربران موبایل ایران با اینترنت محدود.

## بازبینی
در فاز ۷ (PWA) یا اگر بخش تعاملی جدیدی (مثل مدیریت زنده صف تیکت) نیاز شد، اجرای یک ماژول کوچک با جزیره‌های تعاملی (بدون تغییر معماری کلی) بررسی می‌شود.
