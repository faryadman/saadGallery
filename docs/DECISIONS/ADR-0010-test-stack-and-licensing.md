# ADR-0010 — پشته تست و خط‌مشی مجوز بسته‌ها

- **وضعیت:** Accepted (نسخه ۲ — بازنگری‌شده پس از کشف منسوخ بودن xunit v2)
- **تاریخ:** 2026-10-05
- **فاز:** ۱

## زمینه
سند اصلی اجازه می‌دهد باگ‌ها و محدودیت‌ها را در صورت لزوم بپذیریم، اما «تست نباید صرفاً برای رفع خطا حذف شود» و «از نسخه‌های ناسازگار، آسیب‌پذیر یا منسوخ استفاده نکن». برای تست به مجموعه‌ای از بسته‌ها نیاز داریم و هر انتخاب، پیامد مجوز و پشتیبانی دارد.

## تصمیم‌ها

### ۱) xunit v3 (تصمیم اصلاح‌شده — با شواهد)
**انتخاب نهایی: `xunit.v3 4.0.1` + `xunit.runner.visualstudio 4.0.0`.**

تاریخچه تصمیم (شفاف، چون اصل پروژه مستندسازی «چرا» است):
1. ابتدا `xunit 2.9.3` انتخاب شد، چون قالب `dotnet new xunit` در SDK 10.0.401 همان را تولید می‌کند.
2. سپس دستور بررسی بسته‌های منسوخ اجرا شد:
   `dotnet list package --deprecated` ⇒ **xunit 2.9.3 با وضعیت «Legacy» و توصیه به `xunit.v3`**.
3. مطابق اصل غیرقابل مذاکره («از نسخه‌های ناسازگار، آسیب‌پذیر یا منسوخ استفاده نکن») مهاجرت انجام شد.

پیامدهای اجرایی مهاجرت (همه تجربه و ثبت‌شده):
- `Microsoft.Testing.Platform (MTP)` جایگزین VSTest شد؛ در .NET 10 اجرای پروژه‌های MTP از مسیر VSTest **حذف شده است**.
- علت‌یابی خطای «Testing with VSTest target is no longer supported»: راه‌حل رسمی، **opt-in از طریق `global.json`** است:
  ```json
  { "test": { "runner": "Microsoft.Testing.Platform" } }
  ```
  (فایل `dotnet.config` در این SDK مؤثر نبود — آزمون شد و کنار گذاشته شد.)
- بسته‌های `Microsoft.NET.Test.Sdk` و `coverlet.collector` حذف شدند (مخصوص مسیر VSTest).
- دو قاعده تحلیلگر فعال شد که هر دو **اصلاح شدند، نه خاموش**: `xUnit1051` (انتقال CancellationToken در تست‌ها) و `xUnit3003` (سازنده Attribute مشتق از `FactAttribute` با اطلاعات مبدأ).

### ۲) بدون FluentAssertions (تصمیم مجوز)
`FluentAssertions` از نسخه ۸ به بعد تحت مجوز تجاری است. برای پروژه‌ای که مالک آن ممکن است در آینده استفاده تجاری گسترده داشته باشد، افزودن یک وابستگی با ریسک مجوز، منطقی نیست.
- **جایگزین:** `Assert`های خود xUnit. کمی کم‌خوان‌تر، اما بدون ریسک مجوز و بدون وابستگی اضافه.
- سایر جداول: `Shouldly` (BSD) و `AwesomeAssertions` (فورک Apache) بررسی شدند؛ افزودن آن‌ها را به زمانی موکول می‌کنیم که نیاز واقعی به خوانایی بیشتر assertionها ایجاد شود (اصل ۱۱: پرهیز از وابستگی بی‌سود).

### ۳) تست شرطی دیتابیس، بدون «سبز کاذب»
برای تست‌های نیازمند SQL Server، یک Attribute سبک داخلی ساختیم:
`RequiresSqlServerFactAttribute : FactAttribute` که در نبود متغیر محیطی `SADGALLERY_TEST_SQL` مقدار `Skip` را با پیام روشن تنظیم می‌کند.
- **دلیل:** کمترین وابستگی، رفتار صریح، بدون افزودن بسته اضافه.
- در xunit v3، سازنده این Attribute اطلاعات مبدأ (فایل/شماره خط) را هم دریافت می‌کند (قاعده xUnit3003).

### ۴) بدون End-to-End مرورگری در نسخه اول
Playwright/Selenium افزوده نمی‌شود (هزینه نگهداری مداوم برای تیم یک‌نفره). در عوض: تست‌های یکپارچه سطح HTTP با `WebApplicationFactory` + آزمون دستی مستند (docs/TESTING.md §۱).

### ۵) پوشش کد (به فاز ۸ موکول شد)
با مهاجرت به MTP، `coverlet.collector` (مخصوص VSTest) حذف شد. ابزار پوشش سازگار با MTP
در فاز ۸ (سخت‌سازی) ارزیابی و افزوده می‌شود.
- **صداقت:** «Quality Gate پوشش ≥ ۹۰٪ منطق مالی» در `docs/TESTING.md` §۹ یک **هدف** است و تا آن زمان محقق‌شده اعلام نمی‌شود.

### ۶) دارایی‌های سمت مرورگر، self-host
Bootstrap `5.3.8` (RTL + JS bundle) و فونت `Vazirmatn 33.0.3` (مجوز SIL OFL 1.1) **در مخزن** نگهداری می‌شوند، نه از CDN.
- **دلیل:** الف) حریم خصوصی کاربران (بدون درخواست به دامنه سوم)، ب) کارکرد در حالت آفلاین PWA، پ) در ایران دسترسی/CDN نامطمئن است، ت) هیچ وابستگی زمان اجرا به سرویس بیرونی.
- **هزینه:** حجم مخزن (~۳۹۰KB دارایی). مجوز هر دو در کنار فایل‌ها نگهداری می‌شود (`wwwroot/lib/bootstrap/LICENSE` و `wwwroot/fonts/OFL.txt`).

### ۷) قالب Solution: `.sln` کلاسیک (نه `.slnx`)
SDK 10 به‌طور پیش‌فرض `.slnx` (قالب XML جدید) می‌سازد. ما آگاهانه `.sln` کلاسیک را انتخاب کردیم:
- سازگاری با همه نسخه‌های Visual Studio و ابزارهای CI موجود؛
- تبدیل در آینده با یک دستور (`dotnet sln migrate`) و بی‌ریسک است.
- **بازبینی:** اگر مالک از VS 2022 17.14+ یا محیطی کاملاً مدرن استفاده می‌کند، مهاجرت به `.slnx` (مزیت: بدون GUID و بدون تضاد ادغام) بررسی می‌شود.

### ۸) رمزگذاری HTML برای متن فارسی
`WebEncoderOptions.TextEncoderSettings = new TextEncoderSettings(UnicodeRanges.All)` تنظیم شد.
- **دلیل:** پیش‌فرض ASP.NET Core نویسه‌های غیر ASCII را به `&#x635;` تبدیل می‌کند که در سایت تماماً فارسی، حجم پاسخ را چند برابر می‌کند و بررسی متن خروجی/تست را غیرممکن می‌سازد. کاراکترهای خطرناک HTML (`< > & " '`) همچنان رمزگذاری می‌شوند ⇒ ایمنی XSS تغییر نمی‌کند.
- این مورد در فاز ۱ به‌صورت باگ کشف شد (BUG-003 در docs/BUGS.md) و با تست رگرسیون پوشش داده شد.

## پیامدها
- **مثبت:** پشته تست سبک، بدون ریسک مجوز، سازگار با ابزار فعلی، و دارایی‌های self-host که مسئله CDN و آفلاین را حل می‌کند.
- **منفی:** استفاده از xUnit v2 به‌جای v3 (بدهی فنی کوتاه‌مدت، مستندشده) و نبود گزارش‌های assertion خوانا (قابل جبران با پیام‌های دستی در `Assert.Equal(..., message)`).
