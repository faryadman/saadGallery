# ADR-0021 — کش عمومی PWA و به‌روزرسانی با انتخاب کاربر
- تاریخ: 2026-10-19
- وضعیت: پذیرفته‌شده در اجرای فاز ۷ به درخواست مالک.

## تصمیم و دلیل
صفحات MVC حتی برای مهمان می‌توانند توکن ضدجعل داشته باشند و برای عضو محتوای شخصی دارند؛ بنابراین HTML زنده، APIهای عضو، POST و فایل‌های آپلودی مطلقاً کش نمی‌شوند. fallback مستقل offline.html بدون Layout/Identity است. فقط allowlist ثابت دارایی‌ها و یک DTO عمومی نرخ با fetch credentials:omit ذخیره می‌شوند. پاسخ نرخ به schema محدود و رشته‌های قالب‌بندی‌شده سمت سرور محدود است؛ هیچ محاسبه مالی با float مرورگر انجام نمی‌شود. زمان اعلام/دریافت و انقضای مجاز همراه نرخ است؛ انقضا، نبود داده و نمونه آزمایشی روشن می‌مانند. ارسال تیکت آفلاین صف نمی‌شود؛ درخواست POST در قطعی تشخیص‌داده‌شده روی همان فرم متوقف می‌شود.

نسخه انتشار از هش فایل‌های عمومی و شناسه ماژول اسمبلی ساخته می‌شود؛ تغییر frontend/backend و deploy مجدد، بدون الزام تغییر دستی SW، شناسایی می‌شود. manifest دارایی‌های SW دارای integrity است تا انتشار ناقص، کش مخلوط یا پاسخ خطا نسخه فعال قبلی را خراب نکند. install نسخه جدید آن را waiting نگه می‌دارد؛ skipWaiting فقط پیام تأیید صریح کاربر است. activate کش استاتیک نسخه قدیمی را پاک می‌کند و کش عمومی schemaدار نرخ را حفظ می‌کند. سایر Cacheهای origin لمس نمی‌شوند.

اعلان نسخه جدید از چرخه استاندارد SW و بررسی دوره‌ای تب فعال/بازگشت اتصال استفاده می‌کند. فرم dirty و فایل انتخاب‌شده پیش از reload هشدار دارند؛ حالت داده فرم ذخیره نمی‌شود. سایر تب‌ها پس از تغییر controller خودکار reload نمی‌شوند. نصب از beforeinstallprompt در مرورگر پشتیبان و راهنمای Share/Add to Home Screen در iOS است؛ HTTPS معتبر (یا localhost) لازم است. نصب واقعی دستگاه فیزیکی جدا از emulation و CDP گزارش می‌شود. Lighthouse جدید دسته PWA را حذف کرده است؛ گزارش Lighthouse و نتیجه installability پروتکل مرورگر هر دو ثبت می‌شوند.

## مرزها و بازگشت
این PWA جای سرور/SQL و برنامه بومی را نمی‌گیرد. ورود، حساب، تیکت و محاسبه‌گرهای سمت سرور به اتصال سرور نیاز دارند. cache/storage ممکن است توسط سیستم عامل حذف شود. TLS و دامنه Production از طرف مالک هنوز لازم است. schema دیتابیس عوض نمی‌شود؛ برای rollback، نسخه قبلی برنامه را با worker پاک‌سازی‌کننده یا انتشار اصلاحی با شناسه جدید ارائه کنید؛ صرف حذف فایل SW، worker نصب‌شده کاربران را حذف نمی‌کند.
