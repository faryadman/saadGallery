# ADR-0015: دسته‌بندی و پیشنهاد محصولات بر اساس بودجه

- **وضعیت:** کد پیاده‌سازی‌شده؛ در انتظار اجرای SQL Server واقعی، ورودی محصول و تأیید مالک (۲۰۲۶-۱۰-۱۰)
- **دامنه:** افزودهٔ فاز ۴.۱؛ بدون تغییرِ سیاست‌های امنیتی یا قیمت‌گذاریِ فاز ۴

## زمینه

مشتری می‌خواهد دسته‌بندی کند، فیلتر بزند و سقف هزینهٔ خود را وارد کند تا گزینه‌های قابل‌خرید را ببیند. مدل محصول سه سیاست قیمت دارد: `Fixed`، `Computed` و `QuoteOnly`. عددِ محاسبه‌شده فقط وقتی برای تصمیم خرید قابل اتکا است که عکسِ فوریِ قیمت تازه باشد.

## تصمیم

1. فیلترها با درخواست `GET /products` اعمال می‌شوند: دسته، موجودی، بودجه.
2. واحد بودجه **تومان** است؛ این همان واحدی است که قیمت‌های فاز ۴ ذخیره و نمایش می‌دهند (`CurrencyUnit.Irt`). هیچ تبدیل ریال/تومان انجام نمی‌شود.
3. فیلترِ بودجه در کوئری پایگاه داده انجام می‌شود، پس از شرط اجباریِ `IsPublished && !IsDeleted` و پیش از صفحه‌بندی. قیمت ثابتِ مثبت یا عکسِ فوریِ `Computed` با زمانِ محاسبه در بازهٔ تازگی مجاز است؛ مقدار باید `<=` بودجه باشد.
4. نتایج بودجه با گران‌ترین گزینهٔ قابل‌خرید مرتب می‌شوند تا پیشنهادهای نزدیک به سقف بودجه اول دیده شوند.
5. `QuoteOnly`، قیمت ناموجود و عکسِ فوریِ کهنه/نامعتبر از پیشنهاد بودجه حذف می‌شوند. صفحه این محدودیت را به مشتری می‌گوید. کالاهای منتشرنشده هیچ‌وقت از پرس‌وجوی عمومی عبور نمی‌کنند.
6. دسته‌بندی با جدول فعلی `ProductCategories` مدیریت می‌شود؛ Migration تازه لازم نیست. مسیرهای ساخت/ویرایش دسته فقط با Policy سمت سرور `OperatorArea` باز می‌شوند.
7. اسکریپت `SeedGoldCategories.sql` فقط ۶ دستهٔ محصول را می‌سازد و ردیف محصول درج نمی‌کند. در schema فعلی درصد اجرت/سود/مالیات `NOT NULL` هستند؛ مقداردهی صفر برای ساخت draft، دادهٔ مالی ساختگی می‌سازد و ممنوع است. ایجاد محصول تا ورود دادهٔ واقعیِ تأییدشده یا تصمیم جداگانه درباره nullable کردن ستون‌ها متوقف می‌ماند.

## پیامدها و محدودیت‌ها

- تا وقتی محصولات واقعی با قیمت معتبر منتشر نشوند، پیشنهاد بودجه خالی می‌ماند؛ این رفتار بهتر از نمایش یا ساختن قیمتِ فرضی است.
- در محیطی که `SADGALLERY_TEST_SQL` ندارد، آزمون کوئریِ EF/SQL Server اجرا نمی‌شود و صریحاً Skip است؛ آزمون واحدِ پارس مبلغ و آزمون‌های بدون دیتابیس همچنان اجرا می‌شوند.
- برای کاتالوگ کوچکِ گالری، فیلتر با ایندکس‌های موجود و شرط‌های SQL کافی است. در صورت رشد زیاد داده، با آمار واقعی و آزمون Query Plan ایندکسِ قیمت جداگانه بررسی شود.
