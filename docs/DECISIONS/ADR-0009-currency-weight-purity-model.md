# ADR-0009 — مدل واحد پول، وزن و عیار

- **وضعیت:** Accepted
- **تاریخ:** 2026-10-05

## زمینه
الزام سند اصلی: «قیمت‌گذاری ریالی و تومانی را صریح مدیریت کن. هرگز این دو واحد را بدون تبدیل مشخص یکسان فرض نکن.» و «طلای خالص را با طلای ۱۸ عیار اشتباه نگیر. تمام تبدیل‌های وزن، عیار و واحد باید صریح باشند.» و «برای مقادیر مالی از Float یا Double استفاده نکن.»

## تصمیم

### ۱) پول
```csharp
public enum CurrencyUnit { IRR, IRT, USD, USDT }   // ریال، تومان، دلار، تتر

public readonly record struct Money(decimal Amount, CurrencyUnit Unit)
{ /* عملیات فقط با واحد یکسان؛ در غیر این صورت خطا یا تبدیل صریح */ }
```
- **هیچ‌گاه** `Money` ریالی و تومانی به‌طور خودکار هم‌ارز فرض نمی‌شوند. تبدیل فقط با `Money.ConvertTo(target, explicitRate)` و ثبت در Audit/لاگ.
- هر نرخ ذخیره‌شده **همیشه** واحد خود را دارد (`MarketPrice.Unit`). نمایش UI همیشه واحد را نشان می‌دهد (مثلاً «۱۲,۳۴۵,۰۰۰ تومان»).

### ۲) عیار و وزن
```csharp
public readonly record struct Purity(decimal Karat)      // 18 , 24 , 22
{
    public static readonly Purity Eighteen = new(18);
    public decimal Fineness => Karat / 24m;              // 0.750 برای 18
}
public readonly record struct Weight(decimal Grams)      // وزن همیشه «گرم» در لایه داده
{
    public static Weight FromMesghal(decimal m) => new(m * 4.6083m);   // ثابت مستند
    public decimal ToMesghal() => Grams / 4.6083m;
}
```
- **واحد ذخیره‌سازی داخلی وزن، گرم است.** (مثقال فقط واحد نمایش/ورودی است؛ تبدیل در لبه.)
- `Fineness` هم‌ارزِ «عیار/۲۴» است: طلای ۱۸ عیار = ۰.۷۵۰ خالص. این تعریف در یک نقطه از کد است و تست دارد.
- عیار مسکوکات از `CoinDefinition.Purity` خوانده می‌شود (مثلاً مسکوک بهار با عیار ۰.۹۰۰) و **با ۱۸ عیار اشتباه گرفته نمی‌شود** — در محاسبه ارزش ذاتی، ضریب عیار اعمال می‌شود.

### ۳) دقت و گردکردن
- ذخیره: `decimal(18,2)` (ریال/تومان)، `decimal(18,4)` (دلار/رمزارز)، `decimal(9,4)` (گرم/عیار).
- **گردکردن فقط در لبه نمایش** (helper واحد در Web)، نه در محاسبات میانی. از `MidpointRounding.AwayFromZero` برای نمایش پول و از دقت کامل در محاسبه استفاده می‌شود.
- درصد تغییر: `decimal(9,4)` و همیشه با ذکر **دوره مرجع** (مثلاً «نسبت به بسته روز کاری قبل») نمایش داده می‌شود.

### ۴) فرمول ارزش ذاتی و حباب (چارچوب، تأیید نهایی منتظر `Q-COIN-1`)
```
ارزش ذاتی = وزن(گرم) × ضریب‌عیار × نرخ مرجع هر گرم (طلا ۱۸ عیار یا خالص — بسته به تصمیم مالک)
حباب ریالی = قیمت بازار − ارزش ذاتی
حباب درصدی = حباب ریالی ÷ ارزش ذاتی × 100
```
- **نرخ مرجع** و **ضریب عیار** ورودی‌های صریح تابع هستند (نه متغیر پنهان).
- اگر هر ورودی نامعتبر/کهنه/بدون منبع باشد ⇒ خروجی `IsTrusted = false` و هیچ عددی بدون هشدار نمایش داده نمی‌شود.
- `FormulaVersion` در خروجی و در `BubbleCalculation` ثبت می‌شود تا تغییر فرمول در آینده، تاریخچه را بی‌معنا نکند.

## دلیل
- خطای واحد (ریال/تومان) در سامانه‌های نرخ، شایع‌ترین خطای ده‌برابری است؛ مدل نوعی `Money` آن را در سطح کامپایلر محدود می‌کند.
- «گرم» به‌عنوان واحد پایه ذخیره، از خطای انباشته تبدیل‌ها جلوگیری می‌کند و ابهام مثقال استاندارد (۴.۶۰۸۳ گرم) را یک‌جا و مستند حل می‌کند.

## پیامدها
- **مثبت:** تست‌های ساده‌تر و صریح برای مالی؛ حذف کلاس خطاهای «واحد».
- **منفی:** کد کمی طولانی‌تر از `decimal` خام؛ که با سود صراحت و تست‌پذیری موجه است.
- **بازبینی:** پس از `Q-COIN-1` (فرمول و نرخ مرجع) و `Q-CONTENT-1` (فرمول قیمت محصولات)، بخش ۴ تکمیل می‌شود.
