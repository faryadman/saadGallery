# ADR-0002 — SQL Server به‌عنوان تنها پایگاه‌داده

- **وضعیت:** Accepted
- **تاریخ:** 2026-10-05

## زمینه
الزام سند اصلی: SQL Server. محیط توسعه سندباکس ایجنت SQL Server ندارد. برای دقت مالی، به `decimal` با رفتار قابل پیش‌بینی و Index فیلترشده نیاز داریم.

## تصمیم
تنها Provider پایگاه‌داده پروژه: `Microsoft.EntityFrameworkCore.SqlServer` روی **SQL Server**. هیچ Provider دیگری (SQLite/PostgreSQL/InMemory) در کد برنامه ثبت نمی‌شود؛ نه در Dev، نه در تست‌های رسمی.

## دلیل
1. الزام صریح مالک.
2. ویژگی‌های پرکاربرد در این پروژه (Index فیلترشده برای «نرخ جاری»، `rowversion` برای هم‌زمانی، `datetimeoffset`، Collation فارسی) در SQL Server بالغ و آزموده‌اند.
3. تفاوت رفتار Providerها در تست، به «سبز کاذب» می‌انجامد: تستی که روی SQLite پاس می‌شود می‌تواند روی SQL Server بشکند (و برعکس). یک پایگاه‌داده ⇒ یک رفتار.

## پیامدها
- **مثبت:** یکسانی محیط، دقت داده، بدون شاخه‌های شرطی برای Provider.
- **منفی (مستند):** تست‌های یکپارچه در سندباکس ایجنت اجرا نمی‌شوند ⇒ با Trait `RequiresSqlServer` علامت‌گذاری و در نبود Connection String Skip می‌شوند. **این محدودیت پذیرفته شده است** تا صحت تست‌ها حفظ شود. (صادقانه در `KNOWN_LIMITATIONS.md` §1 ثبت شد.)
- `EF Core InMemory` برای تست **ممنوع** است (رفتار SQL را شبیه‌سازی نمی‌کند).

## بازبینی
اگر مالک در Q-DEVDB-1 گزینه «SQLite فقط برای Dev» را انتخاب کند، این تصمیم بازبینی می‌شود؛ اما حتی در آن حالت، تست رسمی همچنان SQL Server می‌ماند و مسیر SQLite هرگز در Production ثبت نمی‌شود.
