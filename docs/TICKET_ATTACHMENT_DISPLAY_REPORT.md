### ۱) چه کاری انجام شد
عکس‌های هر پیام در نمای مشتری و اپراتور پیش‌فرض بسته هستند. کنترل «نمایش پیوست‌ها (تعداد عکس)» عکس‌ها را باز می‌کند و عنوان به «بستن پیوست‌ها» تغییر می‌کند. هر پیام مستقل است؛ پیام بدون عکس کنترل اضافه ندارد. از details/summary بومی مرورگر، مطابق پالت قبلی و با هدف لمسی 44px و focus مشخص استفاده شد؛ بدون JavaScript نیز کار می‌کند.

### ۲) فایل‌های تغییر‌یافته (مسیر + نوع تغییر)
- `src/SadGallery.Web/Views/Shared/_TicketConversation.cshtml`: قرار دادن عکس‌های هر پیام داخل details بسته با تعداد عکس و عنوان نمایش/بستن.
- `src/SadGallery.Web/wwwroot/css/site.css`: ظاهر کنترل، فاصله‌ها، focus، علامت باز/بسته و عنوان متناسب با وضعیت.
- `docs/ROADMAP.md`، `PROJECT_STATUS.md`، `CHANGELOG.md` و این گزارش: معیارهای پذیرش و نتیجه واقعی.

### ۳) تست‌های اجراشده و خروجی واقعی (دستور + خلاصه نتیجه)
- `bash /workspace/.sadgallery-tools/install.sh`: restore و `dotnet build --no-restore -warnaserror -m:4`؛ 0 هشدار و 0 خطا.
- `dotnet test --no-build` با تزریق امن اتصال SQL آزمایشی: 559 موفق، 0 شکست، 0 Skip. هیچ تست قبلی حذف یا ضعیف نشد.
- Chromium/Playwright روی Kestrel و SQL واقعی با کاربر آزمایشی و سه عکس: بسته‌بودن همه عکس‌ها در شروع، تعداد ۳ عکس، نمایش/بستن با کلیک/Enter/Space، کار کردن در موبایل 390 و دسکتاپ 1440 و حالت بدون JavaScript، نبود کنترل روی پاسخ بدون عکس، رفتار مشترک اپراتور، دریافت خصوصی عکس با no-store و نبود سرریز/خطای JavaScript موفق شدند.
