# API و قرارداد داده — SadGallery

> این سند دو بخش دارد: **(الف)** قرارداد ورودی/خروجی نرخ از منبع بیرونی (مبهم تا دریافت نمونه واقعی) و **(ب)** قواعد نگاشت و اعتبارسنجی. API داخلی سامانه در پایان سند و OpenAPI در فاز ۱+ تکمیل می‌شود.

---

## بخش الف — قرارداد منبع بیرونی نرخ

### الف.۱ وضعیت فعلی (صادقانه)
مالک پروژه فرموده «API آماده با خروجی JSON» را خودش ارائه می‌کند. **تا این لحظه هیچ مستند، نمونه JSON، نام دامنه، نوع احراز هویت، یا محدودیت درخواست در اختیار تیم نیست.** بنابراین:
- هیچ حدسی درباره نام فیلد، واحد، فرمت تاریخ، یا ساختار پاسخ زده نمی‌شود.
- هر گونه نگاشت (Mapper) و DTO **پس از** دریافت نمونه واقعی نوشته می‌شود.
- در این سند فقط «قرارداد موردنیاز» و «نمونه‌های مطلوب» تعریف شده است تا مالک بداند دقیقاً چه چیزی لازم است.

### الف.۲ دقیقاً چه چیزی از مالک لازم است (چک‌لیست تحویل)

| # | قلم | چرا لازم است |
| --- | --- | --- |
| A1 | **نمونه JSON واقعی** (پاسخ موفق کامل، بدون ماسک) برای هر Endpoint | تعیین ساختار، نام فیلدها، تودرتویی و انواع داده |
| A2 | Base URL هر Endpoint (طلا/مسکوکات، ارز، رمزارز) و متد (GET/POST) | پیاده‌سازی کلاینت |
| A3 | روش احراز هویت (API Key در Header/Query؟ Basic؟ توکن؟ نام Header دقیق) | طراحی `HttpClient` و ذخیره امن راز |
| A4 | **واحد هر عدد**: ریال یا تومان یا دلار؟ آیا فیلد واحد در پاسخ هست؟ | جلوگیری از خطای ۱۰ برابری |
| A5 | معنی هر فیلد و «کلید دارایی»ها (مثل `gold_geram18`, `sekkeh_emami`) + آیا مظنه ارائه می‌شود؟ | پیوستن به `AssetDefinition` |
| A6 | **زمان اعلام نرخ**: آیا فیلد زمان در پاسخ است؟ فرمت (Unix epoch ثانیه/میلی‌ثانیه؟ رشته ISO؟ بدون Timezone؟) | تفکیک `QuotedAtUtc` از `FetchedAtUtc` |
| A7 | محدودیت نرخ درخواست (تعداد در دقیقه/روز) و جریمه تجاوز | تعیین بازه Job و Rate Limit |
| A8 | شرایط استفاده/حق بازنشر داده (مهم برای نمایش عمومی) | تصمیم نمایش/عدم‌نمایش برخی نرخ‌ها |
| A9 | رفتار خطا: کد وضعیت و بدنه خطا در حالت نامعتبر/سقف‌مصرف | مدیریت خطا و Backoff |
| A10 | نمونه JSON برای **ارز و رمزارز** (اگر منبع جداگانه است) | Provider مستقل (مطابق درخواست شما) |
| A11 | آیا API تاریخی/آرشیو دارد؟ بازه چند روز؟ | تصمیم درباره نمودار و تاریخچه |

> اگر بخشی از این اقلام در دسترس نیست، همان را صریح بگویید تا تصمیم متفاوتی ثبت کنیم (مثلاً «تاریخچه از این منبع ممکن نیست؛ باید خودمان از امروز جمع‌آوری کنیم و به کاربر قدیمیتر از تاریخ شروع نشان ندهیم»). **جمع‌آوری تاریخچه از امروز به بعد، تصمیم قابل قبولی است، اما باید صریح ثبت شود.**

### الف.۳ چهار نمونه JSON که برای شروع فاز ۲ کافی است
فقط ساختار مهم است؛ اعداد واقعی لازم نیست:

```jsonc
// نمونه ۱ — طلا و مسکوکات (مطلوب)
{
  "generated_at": "2026-10-05T10:15:00+03:30",
  "unit": "IRR",
  "rates": {
    "gold_geram18": { "title": "طلای ۱۸ عیار", "value": 7600000, "change": 12000, "quoted_at": "2026-10-05T10:14:52+03:30" },
    "gold_mesghal": { "title": "مثقال طلا", "value": 32800000, "change": -5000, "quoted_at": "2026-10-05T10:14:52+03:30" },
    "sekkeh_emami": { "title": "سکه امامی", "value": 78500000, "change": 150000, "quoted_at": "2026-10-05T10:14:50+03:30" }
  }
}
```

```jsonc
// نمونه ۲ — ساختار آرایه‌ای (مطلوب جایگزین)
{
  "success": true,
  "generated_at": "2026-10-05T10:15:00Z",
  "items": [
    { "key": "usd", "name": "دلار آمریکا", "price": 91200, "currency": "IRT", "change_percent": 0.42, "updated_at": "2026-10-05T10:14:00Z" }
  ]
}
```

```jsonc
// نمونه ۳ — با متادیتای منبع (برای پایش سلامت)
{ "status": "ok", "source": "market-feed-a", "latency_ms": 220, "data": [ /* ... */ ] }
```

```jsonc
// نمونه ۴ — پاسخ خطا (برای مدیریت خطا)
{ "success": false, "error_code": "RATE_LIMIT_EXCEEDED", "message": "..." }
```

### الف.۴ قواعد نگاشت (الزامی — مستقل از ساختار نهایی)
1. **نوع داده:** مقدار عددی به `decimal` نگاشت می‌شود؛ اگر رشته است (`"7,600,000"`, `"۷٬۶۰۰٬۰۰۰"`)، پارسر صریح با تست نوشته می‌شود. **هرگز `double` برای مقدار پولی.**
2. **واحد:** اگر واحد در پاسخ نیست، از تنظیمات منبع (`PriceProvider.Unit`) خوانده می‌شود و در `PriceProvider` **صریح** ثبت می‌گردد. تبدیل ریال⇄تومان فقط با ضریب صریح ۱۰ و با ثبت در لاگ/Audit که تبدیل انجام شده است. **هر نرخ ذخیره‌شده همیشه واحد خود را همراه دارد.**
3. **زمان:** دو مهر زمانی مستقل: `QuotedAtUtc` (اعلام منبع) و `FetchedAtUtc` (دریافت ما). اگر منبع زمان بدون Timezone می‌دهد، منطقه زمانی منبع در تنظیمات ثبت (پیش‌فرض `Asia/Tehran`) و تبدیل انجام می‌شود؛ این فرض **در سند تصمیم ثبت** می‌شود.
4. **کلید ناشناس:** اگر منبع کلیدی بدهد که در `AssetDefinition` وجود ندارد ⇒ **رد رکورد** + `SecurityEvent`/لاگ `Warning` (نرخ ناشناس وارد سیستم نمی‌شود).
5. **گم‌شدن کلید انتظاری:** اگر کلید موجود در `AssetDefinition` در پاسخ نباشد ⇒ هشدار + وضعیت «ناقص» برای آن دارایی؛ جایگزینی با مقدار قبلی به‌عنوان «مقدار جدید» ممنوع است.
6. **اعتبارسنجی بازه:** مقدار باید `> 0` و در بازه منطقی قابل تنظیم (`MinReasonableValue`/`MaxReasonableValue` برای هر دارایی) باشد. جهش بزرگ‌تر از آستانه (مثلاً ۵۰٪ نسبت به نرخ قبلی) ⇒ پرچم `IsAnomaly` + **عدم به‌روزرسانی نرخ جاری تا تأیید اپراتور** (سیاست قابل تنظیم: auto-accept یا manual).
7. **بازه زمانی پاسخ/Timeout:** Timeout پیش‌فرض ۱۰s، حداکثر حجم پاسخ ۲MB، Retry حداکثر ۲ بار با Backoff نمایی فقط برای خطاهای گذرا (5xx/Timeout)، نه برای 4xx.
8. **امنیت SSRF:** `BaseUrl` باید HTTPS و در Allowlist باشد؛ ریدایرکت غیرفعال؛ آدرس‌های IP خصوصی/loopback/metadata مسدود.
9. **پوشش تست:** حداقل ۶ Fixture (موفق، واحد تومان، تاریخ Unix، عدد رشته‌ای، کلید ناشناس، پاسخ خطا/خالی) برای هر Provider.

## بخش ب — مدل داخلی نرخ (قرارداد ما، مستقل از منبع)

```csharp
public sealed record RawRateItem(string AssetKey, decimal Value, CurrencyUnit Unit,
                                 DateTimeOffset? QuotedAtUtc, decimal? ChangeAbsolute, decimal? ChangePercent);

public sealed record ProviderFetchResult(
    string ProviderKey, bool Success, IReadOnlyList<RawRateItem> Items,
    DateTimeOffset FetchedAtUtc, int? HttpStatusCode, string? SafeErrorMessage);
```

- `AssetKey` سپس به `AssetDefinition.Id` نگاشت می‌شود (لایه Application).
- `Quality` نهایی (`Live`/`Delayed`/`Stale`/`Invalid`) در Application محاسبه می‌شود (قواعد در `ARCHITECTURE.md` §4).

## بخش ج — API داخلی سامانه

### ج.۱ قاعده کلی
- نسخه اول **MVC با View** است؛ API عمومی JSON فقط در صورت نیاز واقعی افزوده می‌شود.
- هر Endpoint که برای PWA/نمودار لازم است: زیر `/api/v1/...`، GET، فقط‌خواندنی، بدون داده شخصی، Cache-Control مناسب.
- Endpointهای تغییردهنده (تیکت، محصول، تنظیمات) **فقط POST فرم با Anti-forgery** در MVC؛ اگر روزی API لازم شد، سیاست CSRF/Origin مستند می‌شود.

### ج.۲ Endpointهای عمومی برنامه‌ریزی‌شده
| مسیر | نقش | توضیح | کش |
| --- | --- | --- | --- |
| `GET /api/v1/rates/current` | همه | آخرین وضعیت همه دارایی‌های عمومی + وضعیت تازگی + زمان‌ها | 30s `MemoryCache` + ETag |
| `GET /api/v1/rates/{assetKey}/history?range=24h|7d|30d` | همه (بازه بر اساس Policy) | سری زمانی تجمیع‌شده | 60s |
| `GET /api/v1/bubble/{assetKey}` | همه (جزئیات کامل: اعضا) | ارزش ذاتی، حباب، درصد، نسخه فرمول، `IsTrusted` | 30s |
| `GET /api/v1/health/rates` | همه (خلاصه) / Admin (کامل) | پایش سلامت منابع نرخ | بدون کش |
| `GET /health`, `/health/ready` | سیستم | سلامت سرویس و دیتابیس | بدون کش |

نمونه پاسخ `GET /api/v1/rates/current`:
```json
{
  "fetchedAtUtc": "2026-10-05T06:45:12Z",
  "overallStatus": "Delayed",
  "items": [
    {
      "assetKey": "gold-18k-gram",
      "title": "طلای ۱۸ عیار (گرم)",
      "value": 7600000,
      "unit": "IRR",
      "quotedAtUtc": "2026-10-05T06:44:50Z",
      "quality": "Delayed",
      "providerKey": "primary-feed",
      "changePercent": 0.42,
      "changeReferencePeriod": "previousClose"
    }
  ],
  "warnings": ["یک دارایی نرخ جدید دریافت نکرد؛ مقدار قبلی با برچسب تأخیری نمایش داده می‌شود."]
}
```
> نکته: `changeReferencePeriod` صریح است چون **درصد تغییر بدون دوره مرجع مشخص ممنوع** است.

### ج.۳ قواعد نسخه‌بندی و سازگاری
- افزودن فیلد = مجاز؛ حذف/تغییر معنا = `v2` جدید. تغییرات در `CHANGELOG.md` مستند می‌شوند.
- OpenAPI در فاز ۱ (کتابخانه `Microsoft.AspNetCore.OpenApi`) تولید و در `/openapi/v1.json` منتشر می‌شود؛ Swagger UI **فقط در محیط توسعه** (در Prod غیرفعال — کاهش سطح حمله).
- محدودیت نرخ روی API عمومی: پیش‌فرض ۶۰ درخواست در دقیقه برای هر IP (قابل تنظیم).
